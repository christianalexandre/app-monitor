# ADR-0039 — Swift package layout, protobuf code generation and Swift gates

## Context

PLAN-0003 M2.3 creates `sdk/ios`, the SwiftPM package of the iOS SDK, with
swift-protobuf code generated from `protocol/proto` (ADR-0001, ADR-0008) and a
`make` target for its gates, run as ADR-0037 decided. Already decided: one
`AppMonitor` product, iOS 15, `swift-tools-version: 6.2`, swift-protobuf
(ADR-0003, ADR-0035).

Evidence, checked on 2026-10-23 on this machine (Swift 6.3.3, Xcode 26.6):

- swift-protobuf `1.39.0` (latest tag) ships `protoc` and `protoc-gen-swift`
  as executable products and a `SwiftProtobufPlugin` build plugin that runs
  them on the `.proto` files inside the target's own directory
  (`Package.swift`, `Plugins/SwiftProtobufPlugin/plugin.swift` at that tag).
- No `protoc` on the PATH here. Building both tools from the pinned
  dependency: 25 s (`protoc-gen-swift`) + 40 s (`protoc`, C++ from source),
  cold.
- A SwiftPM target cannot list sources outside the package directory, and
  `protocol/proto` is shared with Wire (ADR-0008).
- Cold `swift test --package-path sdk/ios` (SwiftProtobuf library + tests):
  12 s wall.
- `swift format` 6.3.0 ships with the toolchain; generated files carry
  `// swift-format-ignore-file`.

## Options

1. **Build plugin.** No generated code in git, but the protos would have to
   be copied or symlinked into `Sources/`, and every cold build compiles
   `protoc` (+40 s) — in `make check`, and in every app that adds the
   package.
2. **Generated code committed, regenerated by a script** using the pinned
   swift-protobuf's own `protoc` and `protoc-gen-swift`. Builds and app
   integration cost nothing extra; generated code can drift from the protos.
3. **Generated code in a separate target** (`AppMonitorProto`, public
   visibility) — the generated types become importable by the app, against
   guidelines 01 (small public API).

## Decision

Option 2, generated types `internal` in the `AppMonitor` target.
`make swift-proto` regenerates them into `Sources/AppMonitor/Generated/` and
writes the SHA-256 of `protocol/proto` beside them; `make swift` fails when
that hash no longer matches, then runs `swift format lint --strict` (4-space
indent, 120 columns, `sdk/ios/.swift-format`) and `swift test`. Tests are
Swift Testing and read `protocol/fixtures/` through `#filePath`. `make check`
runs `make swift` only on macOS with `swift` on the PATH and prints one
`swift: SKIPPED` line elsewhere: ubuntu runners also have Swift, and ADR-0037
keeps PR CI unchanged.

## Consequences

- A proto change without `make swift-proto` fails local `make check`; CI does
  not catch it (ADR-0037).
- Local `make check` grows by ~12 s cold, under 1 s warm; CI unchanged.
- Generated code compiles in release too; M2.10 (release stubs) must keep it
  and SwiftProtobuf out of the release build of `AppMonitor`.
