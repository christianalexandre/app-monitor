# ADR-0101 — How the desktop proxy mode is exposed, trusted and fed

## Context

PLAN-0009 M8.1 (c). ADR-0004 layer 4 is an "optional MITM proxy mode in
the desktop with HTTP/2 + gRPC decoding; CA installed automatically on
simulators (`xcrun simctl keychain booted add-root-cert`), manually on
devices. Does not work against certificate pinning", "bound to the local
network and off by default". Every part below is "stop and ask" 4: a
CA that a simulator trusts can read any TLS traffic it carries, and a
proxy accepts connections that are not SDK devices, which ADR-0083's
approvals do not cover. The standing "Local exposure only" decision
(MCP on loopback, LAN devices after approval) is the closest rule; an
option that keeps to it is marked.

Evidence:

- `xcrun simctl help keychain` (Xcode on this machine): `add-root-cert
  [path]` "Add a certificate to the trusted root store", `reset` resets
  the device's keychain.
- A simulator shares the Mac's network stack, so a proxy on
  `127.0.0.1` is reachable from it. gRPC-Core reads `grpc_proxy`,
  `https_proxy`, `http_proxy`, in that order, as an HTTP CONNECT proxy
  (`grpc/grpc`, `doc/environment_variables.md`); `simctl launch` passes
  `SIMCTL_CHILD_`-prefixed variables to the app. `URLSession` follows
  the Mac's system proxy settings.

Already decided, not reopened here: off by default (ADR-0004); the
desktop stores traffic as received (ADR-0081, ADR-0089); devices on the
LAN only after approval (ADR-0083).

## Options

### A. Binding

1. **`127.0.0.1` only.** Simulators reach it; physical devices do not.
   Follows "Local exposure only". Devices stay on layers 1 to 3.
2. **The LAN, with a per-client approval like ADR-0083's.** Devices
   reach it after a click per client address; a second approval list,
   keyed by address, not by device id.
3. **The LAN, open while the mode is on.** Anyone on the network can
   use the desktop as a proxy for that time.

Recommended: 1.

### B. How simulator traffic reaches it

1. **Per app launch, by environment**: the window shows the command
   `SIMCTL_CHILD_grpc_proxy=http://127.0.0.1:<port> xcrun simctl launch
   …` and `make e2e-ios` sets it. gRPC-Core follows it; `URLSession`
   does not, and is already captured in full by layer 1. Nothing on the
   Mac changes.
2. **The Mac's system proxy, set by the desktop** while the mode is on —
   catches `URLSession` too (duplicating layer 1), and routes the Mac's
   own browsers through it; needs an admin prompt and a restore on
   crash.

Recommended: 1.

### C. The CA

1. **One CA generated on first use, per data directory**: its key in
   the data directory with the same file protection as the database
   (ADR-0081), valid 1 year, regenerated by a
   "Reset proxy CA" button that also reminds to reset the simulators'
   keychains. Leaf certificates minted per host in memory.
2. **A CA per proxy session, in memory only** — nothing on disk, but
   every launch needs a reinstall on every simulator.
3. **Bring your own CA** (path in the settings) — a step nobody needs to
   start.

Recommended: 1.

### D. Installing it on simulators

1. **A button "Install CA on booted simulators"** that runs
   `xcrun simctl keychain <udid> add-root-cert <ca.pem>` for each booted
   simulator, showing which ones it changed; never on its own. Devices:
   the window exports the `.pem` and links the manual steps.
2. **Automatic on every booted simulator when the mode is switched on**
   — one click less; changes simulators the developer did not pick.

Recommended: 1.

### E. Hosts and failures

1. **Every host is intercepted**; a client that refuses the leaf
   (pinning) shows as a failed `PROXY` exchange with the TLS error, and
   a "pass through" list in the settings tunnels those hosts untouched.
2. **Only hosts on an allow list are intercepted** — fewer failures,
   and the unknown SDK is again the one not on the list.

Recommended: 1.

### F. Duplicates with the SDK

1. **None by construction with B.1**: the proxy only sees what the app
   sends through the variable, which layer 1 never sees. A gRPC call
   that layer 2 also captured is shown twice, each with its layer
   caption; the window's layer filter hides one.
2. **Match and merge** proxy and SDK exchanges by time, host and path —
   one row, and a guess that can merge two real calls.

Recommended: 1.

## Decision

Empty while `Proposed`.

## Consequences

- A.1 makes the proxy loopback-only, so its lifecycle has no approval
  state; physical devices wait for a later ADR with a concrete case.
- C.1 adds a private key to the data directory: "Clear all data" deletes
  it (ADR-0082 D), and SDD 09 lists it.
- B.1 means a developer launching from Xcode sets the variable in the
  scheme; the window and SDD 02 show both ways.
