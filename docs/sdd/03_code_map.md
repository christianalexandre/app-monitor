# 03 — Code map

Where each part lives in the repository.

## Today

| Path | What |

| `scripts/` | Shell scripts behind `make` targets; `pr_title_check.sh` used by `pr-conventions.yml`; `loop.sh` also backs `make loop-worktree` (`--worktree`, honours `LOOP_WORKTREE`); a failed fetch or `git worktree add` fails both `make loop-worktree` and `make loop` before any iteration; notifications pass the message to `osascript` as an argument, never inside the AppleScript source; its watchdog polls a `.done` marker (ADR-0014) and a timeout is reported only when its `TERM` ended the session (ADR-0015); a session without a verdict waits for a usage limit only on a non-`allowed` `rate_limit_event`, never on the report's text; the verdict is the last non-blank line of the report, only if it is exactly `LOOP: CONTINUE` or `LOOP: STOP [reason]`, so `LOOP: CONTINUE` followed by text, on the same line or after it, is no verdict; it notifies when the worktree's `status: Active` plan changes between iterations (ADR-0019); `swift_check.sh` (`make swift`, skips off macOS), `swift_sim_check.sh` (`make swift-sim`, ADR-0047) and `swift_proto_gen.sh` (wraps the generated files in `#if DEBUG`) / `swift_proto_hash.sh` (`make swift-proto`) for `sdk/ios` (ADR-0039); `swift_api_check.sh` (debug and release public API vs the committed dump, `--update` rewrites it; sources outside `#if DEBUG`) and its tests `test_swift_api_check.sh`, both in `make swift` (ADR-0048); `test_add_local_network_keys.sh` tests `sdk/ios/scripts/add_local_network_keys.sh` on plists, in `make swift` (ADR-0049); `loop_watch.sh` follows the newest `.loop/*.jsonl` and switches when a newer session starts (`LOOP_WATCH_POLL`, default 2 s); `test_loop.sh` tests `loop.sh` and `loop_watch.sh` (ADR-0013) |
| `Makefile` | Command façade |
| `settings.gradle.kts`, `build.gradle.kts` | Gradle root: module list, root lint and `check` |
| `gradle/libs.versions.toml` | Version catalog, shared with `build-logic` |
| `gradle/wrapper/`, `gradlew*` | Gradle wrapper (pinned, checksummed) |
| `build-logic/` | Convention plugins `appmonitor.*` (ADR-0006) |
| `protocol/proto/` | Protobuf schema `appmonitor.v1` (ADR-0008) |
| `protocol/fixtures/` | Golden encoded envelopes, one per message; `masking.json`, the masking cases both SDKs' tests read (ADR-0036 A) |
| `protocol/src/` | KMP module: Wire-generated code, `Protocol` constants, `DesktopSelector` (mDNS answer rule, ADR-0024); `commonTest` round-trip and selector, `jvmTest` fixture check (ADR-0008) |
| `desktop/server/` | JVM module: `AppMonitorServer` (Ktor WebSocket, handshake, frame limit, keep-alive), `EnvelopeRules` (what closes a session with 1002, ADR-0021), `DeviceSession` flows, `DeviceApproval` / `DeviceApprovals` (who gets `HelloAck`, ADR-0027), `MdnsAdvertiser`, `ServerConfig` (ADR-0009); `shutdownHook` and its default report `printStopFailure` (bounded stop at exit, shared with the app); headless `Main.kt` that logs to stdout (ADR-0010); `AppMonitorServerTest`, `ServerHardeningTest` (1009, ping timeout, envelope rules), `DeviceApprovalTest` (pending, 1008, withdrawal), `MdnsPartialFailureTest`, `ServerLifecycleTest`, `ShutdownHookTest`, `MainTest` (`--port` parsing, startup hook) |
| `desktop/app/` | Compose desktop app: `Main.kt` (window + server), `store/` (`TrafficStore`, `TrafficState`), `ui/` (`App.kt` panes, frames and approval panel, `BodyFormat.kt` formats, off-thread `renderBody` and chunks) (ADR-0011, ADR-0029); tests for state, body formats and the offscreen UI; `LiveDeviceScreenshots`, run only by `liveScreenshots` against a real device (ADR-0031) |
| `tools/fake-client/` | JVM CLI: `Discovery.kt` (mDNS through `DesktopSelector`), `Fixtures.kt`, `Replay.kt` (handshake + replay of `protocol/fixtures`) (ADR-0010); `FakeClientTest`, `HandshakeFailureTest`, `MainTest` (CLI errors), `DiscoveryTest` |
| `sdk/core/` | KMP (JVM + Android) SDK core, convention `appmonitor.kmp-sdk` (ADR-0023): `MonitorClient` (states of SDD 04 over a Ktor CIO WebSocket), `EventBuffer` (offline ring buffer), `Backoff`, `Discovery` (sources and mDNS selection, ADR-0024), `MonitorHolder` (start/stop, the process-wide `monitor`), `MonitorBridge` (opt-in `InternalAppMonitorApi` for capture modules, ADR-0025), `AppMonitorOptions` (masking and `maxBodyBytes` included), `DeviceId`, `Platform` (cleartext policy, log); `androidMain` `AppMonitor` (public entry point), `NsdBrowser`, `AndroidDevice` (`Hello`, permission, emulator), manifest declaring `ACCESS_LOCAL_NETWORK`; `commonTest` buffer, backoff, discovery, device id; `jvmTest` `MonitorClientTest` against an in-process `AppMonitorServer`, `MonitorHolderTest` |
| `sdk/android-okhttp/` | KMP (JVM + Android) OkHttp capture, convention `appmonitor.kmp-sdk` (SDD 05, ADR-0025): `AppMonitorInterceptor`, `AppMonitorWebSocketFactory`, `Capture.kt` (sink, masking, bounded request body, event builders); `jvmTest` against `mockwebserver3`, `MaskingVectorTest` on `protocol/fixtures/masking.json` |
| `sdk/no-op/` | KMP (JVM + Android) release artifact (ADR-0026): the public types of `sdk/core` and `sdk/android-okhttp`, same names, doing nothing; depends on OkHttp only; `jvmTest` `ApiMatchTest` (dumps per target), `OptionsDefaultsTest` |
| `sdk/ios/` | SwiftPM package of the iOS SDK, product `AppMonitor`, iOS 15 (ADR-0035); every source but `AppMonitor.swift` and `ProtocolConstants.swift` under `#if DEBUG`, so release compiles to stubs, `api/AppMonitor.swiftinterface` the public API of both builds (ADR-0048): `Generated/` swift-protobuf types (`internal`, committed, `proto.sha256` of the schema they came from, ADR-0039), `ProtocolConstants`; `MonitorClient` (SDD 06's state machine on `NWConnection`, one serial queue, ADR-0040, ADR-0041), `EventBuffer`, `Backoff`; `AppMonitor` / `AppMonitorOptions` (public, ADR-0035; bodies under `#if DEBUG`, range checks in both builds) and `MonitorHolder`; `Discovery` (`discovery(...)`: manual host → `MdnsBrowser` → `127.0.0.1` on the simulator, `DesktopSelector` ported from `protocol`); `BonjourBrowser` (`NWBrowser` plus a TCP probe per name for its IPv4 address, ADR-0042); `Device` (device id file, model name, `appleHello`); `URLSessionCapture` (the CFNetwork hooks of SDD 07 and ADR-0043, `CaptureSink`, per-task `TaskCapture`), `WebSocketCapture` (`WebSocketHooks` on the WebSocket task, ADR-0045), `BackgroundCapture` (`BackgroundHooks` on the background session, per-session `BackgroundTasks`, ADR-0046) and `Masking` (ADR-0036 A); `.swift-format`; `Tests/` Swift Testing `FixtureTests` and `Samples` (the Kotlin samples, field for field) against `protocol/fixtures/`, `MonitorClientTests` against `TestDesktop` (an in-process `NWListener` WebSocket desktop), `DiscoveryTests` with `FakeBrowser`, `BonjourBrowserTests` against an `NWListener` service (multicast-capable interface), `AppMonitorTests` (device id, `Hello`, options as exit tests, holder), `URLSessionCaptureTests` against `TestHTTPServer` (an in-process `NWListener` HTTP/1.1 server) with a `RecordingSink`, its WebSocket cases (`WebSocketCaptureTests.swift`) against `TestEchoServer` (an in-process `NWListener` WebSocket echo), `MaskingTests` on `protocol/fixtures/masking.json`, `LiveServerTests` (only with `APPMONITOR_LIVE_HOST` or `APPMONITOR_LIVE_DISCOVERY=1`); `TestHost/` the XcodeGen spec (`project.yml`, generated project ignored) of the `TestHost` app, with the local network keys Run Script phase (ADR-0049), and its hosted `BackgroundTests` (background sessions on the simulator, sharing `TestHTTPServer.swift`, ADR-0047); `scripts/add_local_network_keys.sh` the Run Script phase an app adds for the Info.plist keys of SDD 06 (ADR-0049) |
| `samples/android/` | Compose sample app, convention `appmonitor.android-app` (ADR-0030): `SampleApplication` (starts the monitor), `MainActivity` (buttons), `SampleCalls` (OkHttp calls to `httpbin.org` and `echo.websocket.org`; `EchoListener` reports the echo once, host test in `src/test`); `src/debug` depends on `sdk/android-okhttp`, asks for `ACCESS_LOCAL_NETWORK` on Android 17+, allows cleartext; `src/release` depends on `sdk/no-op`; `checkReleaseHasNoSdk` in `check` |
